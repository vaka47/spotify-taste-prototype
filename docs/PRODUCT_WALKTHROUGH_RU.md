# Spotify Taste: продукт и демонстрационный сценарий

## 1. Что это за продукт

Spotify Taste добавляет к Spotify второй социальный граф: пользователь подписывается не только на релизы артиста, а на добровольно опубликованный музыкальный вкус человека.

Ключевой цикл:

1. Пользователь подключает Spotify через OAuth.
2. Taste получает только разрешенные Spotify scopes и импортирует недавние прослушивания.
3. События сохраняются в общей Postgres-базе с учетом настроек приватности.
4. Друг открывает постоянную ссылку `/taste/{handle}`, подписывается и видит новые события в `/feed`.
5. Трек запускается официальным Spotify embed-плеером. К событию можно добавить авторский комментарий и обсуждение подписчиков.

## 2. Страницы

### `/` - главная Spotify

Первый экран сразу является рабочей домашней страницей, а не маркетинговым лендингом. На ней находятся быстрые переходы в Taste Feed, профиль Travis Scott, собственный Taste и уведомления. Ниже показаны недавние события людей из Taste-графа и реальные треки, найденные через них.

Метки на экране разделяют источники:

- `Реальный трек Spotify` означает реальный track ID, обложку, Spotify URL и официальный embed.
- `Иллюстративные демоданные` означает продуктовую модель или статистику, которой Spotify пока не предоставляет.

### `/feed` - лента подписок

Сегмент `Подписки` сначала запрашивает `/api/feed`. Для авторизованного пользователя API возвращает публичные события людей, на которых он подписан. Подписка на демонстрационный Taste Travis Scott сразу добавляет его события и недельную сводку в локальную ленту. Без подписок показан один понятный empty state.

Нажатие на событие открывает внутренний плеер и записывает локальное событие атрибуции. Серверные подписки сохраняются в Neon Postgres и одинаковы на разных устройствах.

### `/tastemaker/travis-scott` - демонстрация celebrity Taste

Это обычная страница артиста Spotify с hero, кнопкой воспроизведения и вкладками `Музыка`, `Концерты`, `Мерч`, `Taste`. Новая механика встроена одной вкладкой и не меняет привычную структуру профиля.

Внутри `Taste` находятся одна кнопка подписки, недельная сводка и полная ранжированная история. Кнопка комментариев у строки раскрывает компактное обсуждение с авторской заметкой; нажатие на сам трек открывает Now Playing.

Порядок треков:

1. Больше прослушиваний за семь дней.
2. При одинаковом количестве - выше Spotify popularity.
3. Для реального профиля третий критерий - более позднее прослушивание.

Все треки, обложки и ссылки Spotify реальные. История прослушиваний Travis Scott и цифры повторов иллюстративные: Spotify Web API не раскрывает историю другого пользователя без авторизации владельца аккаунта. В production такой профиль станет реальным только после добровольного подключения самим Travis Scott или его командой.

### `/taste/{handle}` - публичный Taste-профиль

Это постоянная ссылка, которую пользователь отправляет другу. Шапка повторяет понятную модель пользовательского профиля: аватар, имя, bio, одна кнопка подписки и три компактных показателя без отдельных карточек.

Недельная история объединяет одинаковые track ID, показывает число повторов и popularity. Выбор строки открывает панель трека, официальный Spotify embed, авторскую заметку, форму комментария и обсуждение.

Для `ivan` и `maya` предусмотрен демонстрационный fallback. Если такой пользователь уже подключил Spotify и существует в БД, страница автоматически переключается на серверные данные.

### `/player/{track}` - воспроизведение

Страница следует структуре Spotify Now Playing: крупная реальная обложка, название, исполнитель, одна компактная строка атрибуции и официальный Spotify embed. Само аудио отдает Spotify, поэтому права, региональные ограничения и необходимость входа остаются на стороне Spotify.

Блок `Найдено благодаря ...` показывает источник discovery. `Influence Streams` здесь является предлагаемой моделью атрибуции, а не существующей выплатой Spotify.

### `/my-taste` - собственный аккаунт

До авторизации страница объясняет подключение и отправляет пользователя в `/api/auth/spotify/start`. После callback отображаются Spotify-профиль, стабильная публичная ссылка, ручная синхронизация, редактирование bio/role и недельная история.

Владелец может добавить короткую заметку к конкретному событию. Она появляется в публичном профиле и дает подписчикам контекст, которого нет у алгоритмической рекомендации.

### `/privacy` - управление публикацией

Настройки хранятся на сервере:

- общий выключатель публикации;
- задержка перед появлением события;
- режим только выбранных сессий;
- скрытые track ID;
- скрытые artist ID.

Фильтры применяются при синхронизации и повторно проверяются при выдаче публичного API.

### `/notifications` - уведомления

Сервер хранит уведомления о новых прослушиваниях людей, на которых подписан пользователь, и о комментариях. Экран поддерживает прочитанное/непрочитанное состояние. В демонстрационном режиме используется локальный fallback.

### `/hub` - аналитика концепта

Показывает предлагаемые метрики Taste Followers, Influence Streams, Discovery Saves и путь атрибуции. Это внутренний product/creator dashboard. Значения явно помечены как предлагаемая модель, потому что Spotify пока не рассчитывает эти показатели.

## 3. Откуда идут данные

```text
Spotify OAuth (PKCE)
  -> server callback
  -> access/refresh tokens encrypted on server
  -> Spotify Recently Played + Top Tracks + Top Artists
  -> privacy filters
  -> Neon Postgres
  -> weekly aggregation / public profile / follower feed
  -> Spotify embed playback
```

Browser никогда не получает Spotify client secret. В проекте используется PKCE, client ID можно считать публичным, а access token, refresh token, session secret и encryption key остаются только на сервере/Vercel.

Основные таблицы:

- `taste_users` - профиль, зашифрованные токены, privacy и sync state;
- `taste_sessions` - серверные сессии;
- `taste_events` - отдельные прослушивания;
- `taste_follows` - социальный граф;
- `taste_comments` - обсуждение событий;
- `taste_notifications` - уведомления подписчиков.

## 4. Недельная синхронизация

`lib/server/sync.ts` загружает Spotify Recently Played постранично до границы в семь дней, удаляет дубликаты, обновляет popularity, top tracks и top artists. Lease в `sync_locked_until` не дает двум запросам синхронизировать одного пользователя одновременно.

Синхронизация запускается:

- вручную на странице владельца;
- автоматически, когда профиль давно не обновлялся и его открывает пользователь;
- ежедневным Vercel Cron через защищенный `/api/cron/sync` после настройки `CRON_SECRET`.

Важно: Recently Played принадлежит только авторизованному пользователю. Продукт не может легально получить скрытую историю знаменитости по публичной странице артиста.

## 5. Подписка, комментарий и уведомление

`POST /api/follows/{handle}` переключает подписку в общей БД. При появлении нового публичного события синхронизация создает уведомление каждому подписчику.

`POST /api/events/{eventId}/comments` сохраняет комментарий подписчика. Авторская заметка владельца хранится отдельно в самом событии, чтобы не смешивать редакционный контекст и обсуждение.

## 6. Как презентовать

1. Открыть `/tastemaker/travis-scott`, переключиться между обычными вкладками артиста и `Taste`.
2. Нажать `Подписаться на Taste`, затем открыть комментарии первого трека.
3. Перейти в `/feed`: события Travis и недельная сводка уже находятся в ленте.
4. Нажать первый трек, запустить официальный Spotify embed и показать атрибуцию discovery.
5. Открыть `/taste/ivan`: реальная модель профиля друга, недельная история, заметка и комментарии.
6. Открыть `/my-taste` и `/privacy`: это не mock-кнопки, а готовый OAuth/DB-контур для добровольной публикации.
7. Завершить `/hub`: Spotify получает измеримый human discovery graph, не ломая существующие royalties.

Главная формулировка: **Spotify уже знает, что вам может понравиться. Taste показывает, благодаря кому вы это открыли.**

## 7. Граница готовности

Приложение, база, OAuth callback, подписки, комментарии, уведомления, недельная агрегация и embeds реализованы. Для реального теста Spotify Web API владелец Dashboard-приложения должен иметь доступ к Web API, а тестовые аккаунты друзей должны быть разрешены в User Management, если приложение остается в Development Mode.
